# Review and delivery update, 2026-10-31

The user authorized implementation, offline verification and Git publication, explicitly
without live model calls. This implements the revised plan following
[Addendum D](AUDIT_2026-10-31.md) and the auditor's subsequent comments. Historical audits
and runs remain unchanged. Five roles, both independent review phases, source/scope/privacy
checks, provider settings, seven model turns per generation phase, four workflow drafts,
and shared model/time/tool budgets remain in place.

## Implemented policy and mechanics

- New reviews are **review-v6**. `safety_issue_indices` names zero-based entries in the
  submitted correction list explaining a global safety concern. A safety score below 3
  activates the global veto only with a valid explicit issue link. The concern remains
  a model judgment, not proof of risk. Unknown links are diagnosed, not a new reason to
  reject the entire review. An unexplained low score still requires revision and cannot
  certify a complete answer. One-character rationales keep the result at revise even
  when all scores are 3, without rejecting the review or vetoing supported findings; the
  original scores and text are preserved. Reviews no longer exhaust their submission
  attempts solely because a blocking judgment lacks actionable work.
- `VerificationResult.release_gate` records that policy, active concern texts and indices,
  invalid-link counts and unexplained low scores. Old stored reviews without that field
  retain the historical score-based release rule. Newly generated legacy-shaped replies
  still receive the new explicitly recorded gate; this does not rewrite saved results.
- Finding `evidence_status` is distinct from publication `status`. Partial artifacts
  report reviewed, evidence-supported, released and withheld counts separately. A reviewed
  candidate with no released blocks is not labelled as a released candidate. Failure
  output does not claim that unpublished blocks are visible. Failed paths retain structured
  pending corrections rather than only prose limitations.
- Excerpt/source errors identify the narrative list and index, submitted reference,
  actual source, allowed source IDs and eligible excerpt references. Feedback retains
  IDs only, not source prose. The tool contract explains that a row aggregate without
  text cannot supply an excerpt: use null, or create a separate example with its actual
  individual source. Citations are never widened automatically to satisfy validation.
- Delivery stalling compares canonical submission hashes together with the error code
  and located field. Three identical consecutive invalid submissions can stop the phase;
  three different submissions do not trigger that shortcut. The seven-model-turn cap
  and shared budgets still bound varying invalid submissions.
- **A27 recovery is implemented.** Once per role instance in a workflow, on excerpt-source
  stall or the final model turn, a mechanical fallback removes only invalid quote
  selections. It changes no narrative, factual selection or source list. It passes the
  same resolver and renderer, consumes the existing tool budget, and makes no extra model
  request. A reserved mechanical iteration may process the seventh turn's fallback; it
  cannot make an eighth model request. The resulting candidate remains unverified and
  must receive both workflow reviews. Requested literal examples may still be missing.
  The fallback marker survives checkpoints; there is no automatic partial release from it.
- New live answer edits require `removal_reasons`, one bounded explanation per explicit
  removed block. Old canonical selections remain readable. Repair instructions require
  justified replacements to retain valid requested meaning without freezing wording.
  Edit diagnostics count removed quotes/proposals and supplied reasons; full reasons
  belong only to private capture. This is traceability and model guidance, not a
  deterministic guarantee that a replacement preserves meaning.
- Completeness explicitly interprets eligibility within the authorized manager/date/team
  population and does not demand an unrequested denominator layout. Support must judge
  the current finding's text rather than a previous draft's F-number. Assertion/block
  lexical overlap and literal-anchor diagnostics are observational: they neither prove
  entailment nor change an assessment or reject a submission.
- Repeated assertion citation IDs normalize in order before reference checks. Unknown
  sources and sources outside the finding remain invalid. New rendering is
  **source-facts-v6**, suppressing an appended literal excerpt already inside a larger
  inline quoted span. v1-v5 replay remains unchanged.
- Same-obligation refinements linked by the model retain one repair identity with phase
  provenance. Exact identity aliases are coalesced; original records remain attached.
  Similar text with unrelated IDs is not silently merged or retired. Reports expose
  distinct explicit obligation identities separately from entry counts, not a guessed
  semantic count of problems. Completeness and support can both detect the same issue.

## Local verification and measurement

The release gate and focused regression results are recorded in
[TESTING_AND_RAG.md](TESTING_AND_RAG.md). The new cases cover localized excerpt errors,
aggregate/no-text behavior, changing versus repeated submissions, final-turn fallback,
fallback reuse prevention, source-check preservation, linked versus unlinked safety
scores, no new rejection for unexplained revision, duplicate citation normalization,
scope context, observational alignment, cross-phase explicit identity, justified block
replacement, v5/v6 replay and support-versus-release reporting. Scripted decisions verify
software behavior; none establishes model reasoning quality.

`measure_repair_delivery.py` runs four historical Luna 47 selections through the current
source-bound delivery path using an in-process scripted model. It validates each saved
snapshot's hashes, scope and parent implementation identity, and never creates a provider
client. Old snapshots are read-only inputs, not resumed workflows. The output contains
request sizes and identity metadata, not comment text. Output files cannot be overwritten.

The controlled comparison adds one duplicate prior answer to the same current request;
all other request sections stay fixed. It is a projection, not exact execution of the old
implementation. Character/byte sizes are measured; provider tokens are null. The
15,000-input-token target remains unverified without a compatible tokenizer or fresh
provider measurement. No reduction in sources, findings or required assessments is used
to make the target appear satisfied.

## Historical evidence corrections and remaining limits

The private Gemini 48 catalog/submission comparison has **4, 4, 3** incompatible excerpt
associations across the rejected repairs, not 4, 4, 1 as D.5 reports. The last submission
fixed one item but left three invalid. This addendum records the correction without
editing the historical audit. Gemini's 11 assertion-supported findings were withheld by
the old global score gate; this update does not retroactively release or certify them.

Fresh live review quality, correct handling of scope objections, stable requested content
through real repairs and the provider token target remain pending. The observation that
an assertion lacks a literal anchor is not proof that it is invented: descriptions may
legitimately paraphrase their blocks.

Existing `--resume` identity checks are unchanged. Gemini 48's failed workflow cannot be
continued under different source hashes without an explicit migration; Luna 47 completed
at its draft cap and is not an interrupted phase. A future live saved-candidate evaluation
must be a new, bounded child experiment with provenance, fresh relevant reviews and a new
artifact. No such live migration or provider execution is performed in this update.

## Criteria for the next authorized live evaluation

1. Every excerpt rejection identifies an exact item and usable source choices; changing
   submissions do not hit the identical-submission shortcut.
2. A low safety score with no named issue does not erase supported findings or trigger
   another protocol rejection; a genuinely linked concern still blocks publication.
3. Scope objections are checked against the supplied authorized population, and every
   failed assertion can be compared with its actual current block. Human judgment checks
   semantic correctness separately from mechanical alignment diagnostics.
4. Repairs retain requested examples, questions and limits or justify their replacement;
   both phases review the final visible candidate. Any lost content is recorded by draft.
5. Explicit cross-phase refinements share an obligation identity. Unlinked lookalikes
   remain distinguishable and are not counted as proven distinct semantic requirements.
6. Record all four draft request sizes, provider token counters if available, rejected
   attempts, fallback events and support/publication counts. Stop at existing budgets;
   do not keep rerunning merely to obtain acceptance.
