# Addendum C - Runs 43-45, the correction record and delivery-layer defects

This file continues [AUDIT_2026-10-29.md](AUDIT_2026-10-29.md) without editing it, and its
sections are numbered C.x to follow Addenda A and B there. It audits the live pair that followed
the A20-A22 implementation, verifies the reported results, and records the corrections the
earlier addenda still carry. It also refines Addendum B, which summarized the same three runs
before the per-draft evidence below was read.

It is a read-only pass: no live model call, no code change, no test execution, no commit. Every
figure comes from the run artifacts, the exchange captures, the per-draft checkpoints and the
current source at the hashes those runs recorded.

The separation rule of Part B still applies: a **system defect** is a case where the message or
the mechanism could not produce the correct action; **model behaviour** is a decision that was
available and not taken; **design** is a mechanism doing what it was built to do with an outcome
nobody has decided. Observations are filed one at a time, and no row averages the two models.

Rows 19 and 20 are the two mechanisms the pair was run to exercise, and both behaved as
designed. Row 21 is model behaviour that no guard catches: the instructions say never to write
quote text, and the model wrote it; the renderer then adds the same quote again. The defect the
reader sees is deterministic only after the model's mistake, which is why a presentation guard
belongs with the delivery work rather than with a new wording rule. Row 22 is the same class as
the run 41 excerpt regression: a repair rewrites a block that already satisfied the pending
correction.

Rows 23 to 25 are mechanical and visible only because the artifact and the answer are read
together. Row 26 is a reviewer reading, not a content gap. Row 27 is the reason the pair cannot
be averaged: the two deliverables were judged by different strictness. Row 28 is where A21 was
deliberately not narrowed: the validator accepts any known evidence ID, so a real ID attached to
the wrong content passes it, and only the withholding rule removes the finding. Row 29 is a
measurement status, not a finding about a mechanism. Row 30 is outside the system. Row 31 is
mechanical too: `findings.py` `safe_follow_up` maps a missing verdict to a sentence about
conclusions, so a run that produced no candidate still tells the reader that something in the
conclusions needs correction.

## C.6 What the manager received

Run 44 published 16 findings and three limitations: two about verbatim repetition, one about
F5's assertions. The first and third say the same thing in different words ("Verbatim repetition
of the manager action and both follow-up questions..." and "The visible answer repeats several
sections verbatim..."), and the second refers to a finding that is not in the published set.

Run 45 published 15 findings and twelve limitations. Five of them name finding IDs the reader
cannot resolve: F2, F4, F6, F5 and F12. Three of those findings are withheld, so the limitation
describes a block the manager never sees, while the prose classification in the same answer
labels those comments correctly.

The count reconciliation is exact once duplicates are removed: 15 pending entries collapse to 12
distinct texts. The three extras are P11, P12 and P14, which repeat P07, P08 and P09 word for
word, and their `correction_id` prefixes differ: the same complaint was re-issued against a
different candidate and entered the list again under a new ID. `zero_sugar.py:1444-1453` retains
an unresolved obligation by ID even when its wording matches another item, which is the intended
behavior for one obligation and the reason the count grows with drafts when a complaint is
re-issued. The manager-facing number should therefore be the distinct obligation count, not the
entry count.

Two findings are published with a limitation that contradicts their support: F5 and F12 appear
in the released set and in the unresolved list as "contradicted or insufficiently supported
assertions". F2, F4 and F6, judged the same way, are withheld. Either the release rule and the
withholding rule answer different questions, in which case the difference should be stated, or
one of them is inconsistent. This audit does not decide which; it records that the reader is
told a published finding is unsupported.

The failed run shows the same weakness from the other side. Run 43's whole answer is:
"Echo could not connect to the model provider." followed by "Some conclusions or their
presentation still require correction." The second sentence is the `safe_follow_up` fallback for
a run with no verdict, and it describes a defect in conclusions that were never produced. A
failure text is part of what the manager reads, so it should report the judged, supported and
released counts, or say that none exist.

## C.7 The sentiment calculation and the reviewer readings

The aggregate is identical in both runs and arithmetically consistent: 9 + 2 + 0 + 2 + 0 = 13
eligible comments, and 69.23 + 15.38 + 0 + 15.38 + 0 = 99.99, which is the rounding of 9/13,
2/13 and 2/13. The denominator is stated in both answers (44 in the limits paragraph, 45 in the
limits paragraph and as a column). No artifact from either run shows a deterministic counting or
percentage defect.

The labels are a different matter, and they are model judgment. Run 45's F2 calls CMT27512 mixed
while the same answer's prose list calls it positive. The finding is withheld, so the
contradiction does not reach the manager as a finding; the limitation that names F2 keeps the
complaint visible without the block that would explain it.

The two reviewers did not apply the same criteria:

- Gemini's reviewer raised the per-comment classification at draft 1 ("individual classification
  of each of the 13 comments not shown") and did not carry it to draft 4, where completeness
  accepted the draft that has no such classification.
- Luna's reviewer kept the demand at draft 4 and framed it as a missing table while its own
  correction text says "only prose list shown", asked for a "denominator row" while the
  denominator is stated, and wrote that "positive excerpt and critical excerpt each appear
  twice" when the positive excerpt appears zero times and the repeated text is the mixed
  comment.

The question asks to classify each comment and to show the count and percentage per category with
the denominator, and to include a short literal excerpt for a positive and a critical view. It
asks for the classification; it does not ask for a table that displays every comment. The
classification and the denominator exist in run 45, the table does not, and the positive excerpt
does not either. The missing table is a format demand beyond the request; the missing excerpt is
a real omission; both arrived under the same correction.

## C.10 Limits of this audit

- Read-only pass over three artifacts, their exchange captures, the per-draft checkpoints, the
  manifests and the current source. No model call, no test run, no code change, no commit.
- Counts are mechanical: calls and events from the captures, findings and release sets from the
  artifacts, characters and token counts from the logged requests, duplication from Jaccard
  overlap with the method stated in C.5.
- No label, citation, correction or claim was graded semantically. Where the answer and the
  review disagree, this file reports both and does not decide which reading of the question is
  right.
- One pair per provider, with generator and reviewer served by the same model in each run. Any
  difference between 44 and 45 can be a provider difference, a reviewer difference, or both.
- The sentence-level behavior in row 21 is read from `grounding.py:369,383-386`: the excerpt is
  appended to every sentence unit of a multi-sentence item. Both affected items in these runs
  were single sentences, so the sentence-level case is a code reading, not an observation.
- The run inspector was not regenerated for runs 43-45 in this pass; its last build covers the
  earlier runs.
- Nothing here relaxes the correction-state rule, the evidence-ID rule, the draft cap or the
  attempt cap, and nothing reduces findings, sources or assertions to make an outcome fit.
