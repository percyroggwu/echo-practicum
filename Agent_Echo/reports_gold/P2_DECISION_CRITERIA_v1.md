## Stop condition (M1, M2, M3, M4)

Both baselines have 0 protocol failures. Any new protocol failure stops the evaluation of that
measurement. It is diagnosed first and is not counted as evidence for or against any line.

## M1: group A

Repeats 1 on both profiles.

- A profile regresses when, against its baseline, it has more false objections, more missed
  defects or more wrong decisions.
- Both profiles regress: revert line A.
- Neither profile regresses: keep line A.
- Exactly one profile regresses: run one more `apinex_gemini_test` repeat. Revert line A if
  that repeat also regresses against the Gemini baseline; keep it otherwise.

## M2: group B

Repeats 2 on both profiles.

- Decision metric: destructive repairs in R1-R5. Revert the three group B lines if either
  profile exceeds its baseline (apinex_test more than 1, apinex_gemini_test more than 2).
  Keep them otherwise.
- R6 (following a false correction) is reported separately and does not decide group B.
- Model calls and tokens are reported and do not decide; they are confounded by the
  priority 1 `label_group` normalization.

## M3: planning (no baseline; first planning measurement)

Repeats 2. A case-run passes when the final plan, after `plan()` and its reconsideration,
matches the expected plan on `needs_numbers`, `needs_text`, `needs_sentiment`,
`include_chart`, whether a clarification is asked, and the set of `metrics`.

- Hard cases pass in every repeat: the question from live runs 63-66, and every case that must
  not ask for clarification.
- Overall: at least 85% of case-runs pass.
- A failure is recorded as an observed failure. A new prompt rule is allowed only when the same
  failure appears in both repeats or in two different cases, and the commit cites it.
- The raw model plan, before code normalizations, is reported as a diagnostic, not as the pass
  criterion.
- The 85% threshold and the hard-case list have no prior data. They are revisited after the
  first M3 run, in a new version of this file, and apply from the next run.

## M4: group C

M4 is separate from the frozen v1 casebook. It has three cases, one per group C line:

1. An answer that explains that requested evidence is unavailable.
2. A `task_outcomes` entry for a declined or failed specialist task.
3. An answer with a chart.

M4 runs before step 7 (merge) and costs about 6 calls per profile.

- Keep a group C line only if M4 shows that the failure it prevents is otherwise mishandled:
  a false objection, a repair loop, or a false "data absent" claim. Revert it otherwise.
- If M4 is not run, revert all three group C lines.
