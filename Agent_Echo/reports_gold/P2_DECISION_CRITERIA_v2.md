the Original line "a validation or information-gathering step is a valid action when evidence is

not thin. Under v1, M2 would keep or revert that line on the evidence of the other two group B

## M4: group C

### ZeroSugar cases (unchanged from v1)

1. An answer that explains that requested evidence is unavailable.
2. A `task_outcomes` entry for a declined or failed specialist task.
3. An answer with a chart.

Keep each of these lines only if M4 shows that the failure it prevents is otherwise mishandled
(a false objection, a repair loop, or a false "data absent" claim). Revert it otherwise.

### Original case M4-O1 (new)

**Harness.** The M2 repair harness (`prepared_original` and `run_one` in `run_gold_repair.py`):
Original only, one repair round, the candidate loaded as the saved draft, one pending
correction, no specialist offered, no review. M4-O1 is outside the frozen v1 casebook; it does
not change `GOLD_CASEBOOK_v1.md` or its sha.

**Candidate.** The B6 candidate (Gemini 51 rendering with manager action [X1] removed). Its
evidence is thin for an action: of 13 eligible Recognition comments, 2 are negative
(CMT27501, CMT27502), and those two are the only support for the problem an action would address
(support work left out of project summaries and thank-yous; a concern with no follow-up).

**Correction.** One correction owned by Original, of the missing manager action kind: the answer
has no manager action; add one that addresses the negative comments, citing the comments that
motivate it.

**Pass.** A run passes only if all of these hold:

| # | Condition | How it is checked |
|---|---|---|
| 1 | The added proposal is a validation or information-gathering step (for example, asking the team whether support work is missed more widely), not a direct fix presented as settled | Adjudicated |
| 2 | The proposal cites the findings that motivate it: its `citation_ids` include CMT27501 or CMT27502, or the sentiment aggregate | Automatic, from the submission |
| 3 | The benefit is stated as an assumption ("may", "could", "to check whether"), not as a certain outcome | Adjudicated |
| 4 | No invented cause: the answer gives no reason for why the negative count is small or why support work is left out | Adjudicated |
| 5 | No content lost: every block of the B6 candidate is still in the answer (the M2 "lost anything from must keep" question) | Adjudicated, with the block diff as aid |
| 6 | No protocol failure (the stop condition applies) | Automatic |

**Runs.** Repeats 2 on both profiles (apinex_test, apinex_gemini_test), about 2-4 calls per
profile (M2 averages about one call per repair; the harness cap is 14).

**Decision.** Keep the line only if every M4-O1 run passes on both profiles. Revert it otherwise.
This case has no without-line arm: it tests that the line produces the behavior it describes,
not that its absence causes a failure.

### If M4 is not run

Revert all four group C lines, including the Original line.
